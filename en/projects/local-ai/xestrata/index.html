XeStrata on an Arc Pro B60

XeStrata running qwen3.8-flash-next-gyro-gyro-s on a 24 GB Intel Arc Pro B60: the machine, the ways to measure it, and real numbers from 49 behavioural tests.

The engine, the weights and the loop guard come from other projects. What is mine here is the deployment, the gyro-bench harness and the measurements. The numbers come from one real run on 14 November 2026 with --seed 7 --repeat 3, and its limits are documented on the same page.

The model running here

A large MoE on a 24 GB card

The engine is XeStrata (strata, version xe0.2.8-1). Its central idea is that the model does not fit in VRAM as a whole, so it decides which part lives on the card and pulls the rest on demand.

Model
qwen3.8-flash-next-gyro-gyro-s, the name /health and /metrics return. 131,072 token context, int8 KV, image input enabled.
Weights
Qwen3.8-Flash-Next-Gyro-S-TQ1_0.gguf: 58,487,015,808 bytes (54.5 GiB) on NVMe. The derived weights come from public Qwen model weights published by ISTA-DASLab and agentionai.
MoE
48 layers with 512 experts each: 24,576 blobs of 1.0 MiB, 24.0 GiB in total. The card cache holds 11,383 slots (11.1 GiB), 46% of the expert model.
Missing experts
They resolve through RAM or the PCIe link (pcie_frac 0.38). In the run the expert cache hit rate was 0.66–0.995, and requests with a cache hit read nothing from the GGUF (0.0 MB).
Speculative
MTP (mtp/rt) with mtp_max 4 and lookup 3. The start line passes --spec 4 and the engine reports spec 6 with spec_window auto.
Vision
A separate process: strata-vision-vulkan with mmproj-Qwen3.8-Flash-Next-BF16.gguf and --max-tokens 1024.
Thinking
reasoning_effort accepts none, low, medium, high; the default is high. The loop guard comes from Project Maya.

XeStrata is a fork of Strata maintained by MistVVK, licensed LGPL-3.0-or-later (Strata upstream is MIT). The measurements on this page come from my own start line, not from an official XeStrata benchmark.

The machine

Specs read from hardware, not from the label

The values come from lspci, /proc/cpuinfo, free and the engine's own /metrics. Intel's product page confirms the PCI device.

GPU
Intel Arc Pro B60 (Battlemage G21 family, Xe2 microarchitecture). PCI 0000:03:00.0, device 8086:e211, subsystem ASRock 6023, kernel driver xe.
Card
20 Xe cores, 160 XMX and 160 Xe vector engines, 2400 MHz clock, 12.28 TFLOPS FP32, 197 TOPS int8, 200 W TBP.
GPU memory
24 GB GDDR6 at 19 Gbps over a 192-bit interface: 456 GB/s. The engine reports 23.9 GiB usable and 20.8 GiB occupied during the run (58–69 °C, 35–96 W).
Link
PCIe Gen4 x8 active (the chip's maximum is Gen5 x8). This is the bottleneck when experts do not fit.
CPU
12th Gen Intel Core i5-12400F: 6 cores / 12 threads. Relevant instructions: AVX2 and VNNI; no AVX-512 on this machine.
RAM
32 GB physical, 31.2 GiB visible; 23.9–24.7 GiB occupied during the run (model + server + other sessions).
Storage
NVMe SSD holding weights, pack, MTP and logs.
System
Ubuntu 24.04.5 LTS. XeStrata installed from source at /mnt/local-ai-nvme/LocalAI/XeStrata, no deb package.

Deployment

An OpenAI-compatible server on localhost

Three processes: the HTTP server, the strata --serve engine and the vision process. The API is http://127.0.0.1:8095/v1, plus /health and /metrics.

.venv/bin/python serve/server.py --engine strata \
  --config xestrata-gyro-vision.json --host 127.0.0.1 --port 8095

engine/strata --serve --pack packs/gyro-gyro-s \
  --native Qwen3.8-Flash-Next-Gyro-S-TQ1_0.gguf \
  --ple-gguf Qwen3.8-Flash-Next-Gyro-S-TQ1_0.gguf \
  --expert-profile data/expert-profile.bin --expert-cache auto \
  --prefill auto --spec 4 --spec-min-p 0.5 --mtp mtp/rt \
  --max-context 131072 --kv int8 --resident-experts \
  --vram-reserve-mib 2048 --prefill-cpu-share 0.79 \
  --vram-free-mib 22179 --vision

engine/strata-vision-vulkan --mmproj mmproj-Qwen3.8-Flash-Next-BF16.gguf \
  --model Qwen3.8-Flash-Next-Gyro-S-TQ1_0.gguf --gpu --gpu-pci 0000:03:00.0 \
  --max-tokens 1024
  • The build is local: contrib license with Intel's own LLVM, not a package download.
  • ~/.config/xestrata/settings.json holds card data and keys; they are not published.
  • The first start is slow: the engine builds the pack and fills the expert cache before answering.
  • The real requirements, the quantizations available and the four installation routes are in Running local AI.
  • The run was launched with the server nearly free: 24 of 28 graded requests have a queue below 60 ms and the other 4 ended up behind another generation.

Three ways to measure

Speed, behaviour and engine counters

These are three different things and should not be mixed: raw speed, model behaviour and the engine's internal counters.

ToolWhat it answersWhere the numbers come fromCost
gyro-bench (mine) Does it behave well: thinking, tools, schema, needle, loops? HTTP against a live server: per-request timings + /metrics + /health. ~2 min --quick, ~4 min full
xestrata --bench How many tokens/s per prompt size and quantization? XeStrata's own benchmark; writes records/bench-<time>/. ~40 min
/metrics and /health What is the engine doing right now (cache, experts, hardware)? Global counters since start plus the buffer of the last 500 requests (requests=all). instant read

What the run shows

Six things useful for anyone building a similar machine

01

The conversation cache is the biggest saving

The same 6,439 token prefix went from 0% KV reuse to 99.9% (6,432 of 6,439). The first pass TTFT was 11,314 ms and the following ones 137–144 ms.

02

Prefill and cache are different figures

The cold prefill of the needle's 15,322 tokens runs at 748–762 tok/s; the passes with the prefix reused drop to 65–68 tok/s because almost no compute is left. The figure that matters there is TTFT, not tok/s.

03

Thinking has a measurable price

Across four problems, each one 3 times: none reasoned 0 tokens and got the 2 gradable tasks right (the bat-and-ball and trains traps stay expected-fail); low, medium and high got 4 of 4 right with 978, 942 and 1,000 reasoning tokens.

04

Concurrency barely scales

batch_slots: 0: the engine serves one request at a time. With 2 requests the scaling was 1.22× and with 4, 1.06×. That is an engine property, not a model one.

05

Speculative decoding multiplies decode

1,639 drafts accepted out of 2,386 offered (68.7%). The engine decode median was 37.3 tok/s (16.6–63.2), and the real wall clock rate is much lower because it includes prefill and TTFT.

06

The loop guard intervenes

On a repetition-prone prompt: 35 words with 3 unique ones; detected 2, penalised 1, stopped 1. Without that guard the output repeats until the limit.

Limits

What this run means and what it does not

Real limits of these numbers

  • The run was launched with the agent quiet, and still 4 requests waited 2,460–8,198 ms in queue: their TTFT stays marked as contaminated (ttft_clean: false).
  • Pairing with /metrics uses the started..finished window and counters, because the server does not expose request ids.
  • /metrics shows the last 12 records and its buffer keeps 500: the harness asks for requests=all.
  • With seed 7 the 16 thinking tasks repeated the same answer; across runs without a seed, thinking changes.

Non-goals

  • Not a speed benchmark: that is what xestrata --bench is for.
  • No claim of sustained or multi-user throughput: batch_slots: 0 serves one request at a time.
  • Does not test other quantizations or other cards.
  • Not a product: it is a measurement of one personal deployment.

Reproducibility: the data is in run-2026-11-14.json (49 cases with their metrics, the /health and /metrics snapshots, and the caveats). The run uses --seed 7 --repeat 3, so another run with the same options is comparable; the full raw output lives in the harness repository.
