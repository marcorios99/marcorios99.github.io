FormVision

Procesamiento estructurado de formularios con QR, OMR, OCR e ICR.

Proyecto MIT completo para su alcance de portafolio: una demo pública, sintética y segura para la privacidad, no un benchmark productivo.

Del problema a la salida

Captura repetitiva, convertida en resultados verificables

  1. 01

    Problema

    Los formularios estructurados escaneados requieren transcribir, revisar y validar datos repetitivos antes de poder utilizarlos.

  2. 02

    Solución

    Una plantilla de referencia y un layout explícito conservan la geometría conocida de cada campo durante el procesamiento.

  3. 03

    Resultado

    El pipeline devuelve un FormProcessingResult validado que puede exportarse a JSON, CSV o SQLite.

Pipeline

Dos contratos de imagen, una salida estructurada

El QR y los fields siguen rutas distintas deliberadamente: QR preserva la página alineada completa; los fields se extraen de ROIs sobre la imagen limpiada.

  1. 01

    Entrada y alineamiento

    image path → ImageLoader → alineamiento opcional contra la referencia → aligned.

  2. 02

    Dos ramas

    aligned → QR de página completa. MagentaDropout → cleaned → ROIs definidos por layout.

  3. 03

    Extracción

    Las ROIs de cleaned se despachan a OMR, ICR u OCR según el tipo de field.

  4. 04

    Validación y exportación

    Los validadores producen FormProcessingResult, disponible mediante exporters JSON, CSV o SQLite.

Plantilla y layout

Geometría explícita en lugar de detección universal

La plantilla pública synthetic_omr_v1 mide 1240 × 1754 y define 12 fields: 8 OMR, 1 ICR y 3 OCR. layout.json declara page_size, ROIs, validadores y opciones OMR.

El editor layout_viewer.html permite cargar una imagen y un layout existente, mover o redimensionar ROIs y guardar el JSON.

No detecta fields automáticamente: la geometría forma parte del contrato de la plantilla.

Motores

Cada tipo de dato tiene un alcance explícito

QR

OpenCV

Se lee con cv2.QRCodeDetector sobre la página aligned completa. No es una ROI ni un field del layout.

OMR

Marcas configuradas

Aplica Otsu y puntúa regiones centrales de opciones declaradas; es deliberadamente simple y específico para la geometría configurada.

OCR

docTR pretrained

El adaptador recibe una ROI y usa pesos pretrained. Puede requerir conexión para descargar pesos en el primer uso; no hay entrenamiento OCR local.

ICR

Referencias MNIST

Segmenta dígitos separados y usa vecinos cercanos con voto ponderado sobre el banco incluido. No es una red neuronal entrenada.

Demo pública

Reproducibilidad sin datos privados

La demo preparada usa diez scans sintéticos, ground truth por formulario y el artefacto ICR ya incluido. Formularios, identidades y respuestas son sintéticos o públicos.

python -m pip install -e ".[full]"
python demo.py
  • MNIST no se descarga ni se entrena para ejecutar la demo preparada.
  • docTR puede descargar pesos pretrained al primer uso.
  • El lote escribe data/outputs/demo/report.json.

Evaluación

Reporte JSON de lote, no promesa de producción

El reporte de esquema 2.0 registra formularios procesados, errores, comparaciones por field y resultados agregados por motor, incluyendo accuracy y coverage cuando corresponde.

  • Un batch completado indica que el procesamiento y la evaluación terminaron; no implica precisión perfecta.
  • No hay quality gate productivo ni reporte HTML.
  • La demo se presenta como integración y reproducibilidad, no como benchmark productivo.

Criterio técnico

Decisiones que hacen explícito el contrato

01

Assets sintéticos y reproducibles

Motivo
Publicar una demo verificable sin exponer formularios, reglas o identidades privadas.
Trade-off
La variabilidad sintética no mide rendimiento en producción.
02

Referencia, ROIs y QR separados

Motivo
Preservar geometría conocida y mantener claro qué consume cada etapa.
Trade-off
La plantilla y la referencia son requisitos, no inferencias automáticas.
03

Motores opcionales y evaluación fuera del Core

Motivo
QR/OMR siguen ligeros; OCR/ICR y la evaluación tienen contratos explícitos.
Trade-off
docTR puede requerir instalación y descarga de pesos; el artefacto ICR se distribuye para evitar reconstruirlo.

Límites

Alcance intencionalmente acotado

Limitaciones reales

  • Formularios estructurados y controlados; no hay detección universal ni automática de fields.
  • El alineamiento requiere una referencia cuando está habilitado.
  • ICR admite dígitos separados, no cursiva ni dígitos tocándose.
  • OCR es pretrained y OMR es simple y específico del layout.

Non-goals

  • No soporte de documentos arbitrarios ni de PDF.
  • No reporte HTML ni visualización de etapas intermedias.
  • No afirmaciones de precisión productiva.
  • No roadmap activo de producción: el proyecto está completo para su alcance de portafolio.
